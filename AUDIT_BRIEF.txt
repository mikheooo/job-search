--------------------------------------------------------------------------------
1.1. Назначение и целевая аудитория
--------------------------------------------------------------------------------
job-search — персональная полуавтоматическая система поиска удалённых вакансий, оценки соответствия квалификации (матчинга), формирования адаптированных сопроводительных материалов и контролируемого отклика на платформе HeadHunter (hh.ru), а также триажа сообщений от рекрутеров.

Проект разработан для конкретного пользователя (Михаила Колесникова) под целевой профиль:
- P1: AI Automation Engineer, Application Support Engineer, Technical Support Engineer (L2/L3);
- P2: Python Backend Developer (Junior+/Mid), System Administrator / IT Systems Engineer;
- P3: Data Engineer / ETL Developer, DevOps / SRE Junior.


--------------------------------------------------------------------------------
1.2. Этап развития и пользователи
--------------------------------------------------------------------------------
- Текущий этап: Активная разработка / Эксплуатация персонального продакшна (Stage 92 по внутренней классификации коммитов и спецификаций).
- Пользователи: 1 реальный пользователь (владелец/оператор).
- Степень автономности: Гибридная («Human-in-the-loop»). Действует жесткий принцип: по умолчанию система работает в режиме REVIEW (любые внешние мутации требуют явного подтверждения оператором). Автоматический режим (AUTO) изолирован программными kill-switch флагами.
- Фактический объем данных: В БД зафиксировано 714 проверенных вакансий, 37 канонических вакансий, 22 записи о доставке дайджестов в Telegram (13 единичных вакансий, 4 батча), 1 реальный отклик через runner, 1 реальный клик по кнопке фидбека в Telegram.

3.2. Циклические зависимости и отложенные импорты
--------------------------------------------------------------------------------
Статический граф модулей верхнего уровня не содержит циклических зависимостей (find_cycle = []).  
Однако это достигнуто за счет массового использования отложенных локальных импортов внутри функций (lazy imports).
- 28 модулей внутри ai_assistant/ содержат вызовы import или from . import непосредственно внутри тел функций и методов.
- Основной узел сцепления — ai_assistant/db.py, ai_assistant/cli.py и ai_assistant/application_tracking.py. Модули импортируют функции друг друга внутри методов, чтобы избежать ImportError на этапе компиляции модулей.


--------------------------------------------------------------------------------
3.3. Ключевые пользовательские сценарии (End-to-End)
--------------------------------------------------------------------------------


>>> Сценарий 1: Регулярный сбор вакансий, скоринг и доставка дайджеста в Telegram
1. Триггер: Планировщик Windows Task Scheduler запускает scripts/run_job_search_production.ps1 -> python -m ai_assistant.cli production-run.
2. Блокировка и проверка безопасности: ai_assistant/runner.py:run_production_pipeline захватывает файловый лок job_search.lock. Проверяет статус прерывателя цепи (ConsecutiveFailureTracker в logs/job_search/failure_tracker.json). Если зафиксировано $\ge 3$ подряд идущих сбоев, запуск немедленно прерывается с кодом 5 (PRODUCTION_CIRCUIT_OPEN).
3. Сбор: Запускается integrations/hermes/job_search_fetcher.py. Модуль Watcher опрашивает сетевые адаптеры (adapters/himalayas.py, remoteok.py, weworkremotely.py, habr_career.py).
4. Нормализация и идентификация: normalizer.normalize_vacancy приводит данные к модели Vacancy. vacancy_identity.resolve_vacancy_identity вычисляет канонический идентификатор и алиасы.
5. Матчинг: JobMatcher.match оценивает вакансию по профилю candidate_profile.json (проверка зарплатного минимума \$1,500, запрет на не-ремоут, соответствие стека). Вычисляется класс решения (STRONG_MATCH, MATCH, STRETCH, BORDERLINE, REJECT) и балл (0–100).
6. Сохранение: db.save_vacancy сохраняет вакансии в таблицу vacancies базы state.db.
7. Формирование дайджеста: cli.export_digest_cmd выбирает вакансии, удовлетворяющие критериям: подтвержденный источник, статус решения APPLY/REVIEW, балл $\ge 60.0$, отсутствие записи DELIVERED в telegram_delivery_records. Применяется ограничение разнообразия (максимум 2 вакансии на компанию, 4 на семейство ролей).
8. Отправка: db.record_digest_attempt переводит статус в ATTEMPTING. Скрипт отправляет сообщение в канал @remotejobd через Telegram Bot API с inline-клавиатурой [👍] [👎] [📄] [⏭].
9. Фиксация доставки: db.mark_digest_delivered переводит запись в статус DELIVERED.


>>> Сценарий 2: Интерактивная обработка фидбека из Telegram (Human-in-the-Loop)
1. Триггер: Пользователь нажимает кнопку под вакансией в Telegram (например, 📄 Отклик).
2. Маршрутизация: Hermes Gateway перехватывает callback fb:APP:<target> через хук integrations/hermes/telegram_adapter_hook.py и передает его в ai_assistant/telegram_feedback.py:TelegramFeedbackProcessor.
3. Проверка авторизации (Owner Authorization Gate): Проверяется, что callback_query.from.id == TELEGRAM_OWNER_ID (392046103). Запросы от любых других пользователей отклоняются с сообщением ⛔ Доступ запрещён.
4. Проверка идемпотентности и источника: Проверяется callback_query_id (защита от повторных нажатий) и подтверждается, что вакансия действительно доставлялась в дайджесте (is_vacancy_delivered_in_digest).
5. Трансформация состояния:
   - Для действия 📄 Отклик: создается одобренная запись ревью в application_reviews (APPROVED), статус в application_tracking переводится в READY_TO_APPLY, вакансия помещается в application_queue. Вакансия НЕ отправляется работодателю автоматически.
   - Для действий 👍 / 👎 / ⏭: выставляются статусы ANALYZED, REJECTED или WITHDRAWN.
6. Аудит: Запись о фидбеке сохраняется в таблицу telegram_feedback_records.
7. Ответ Telegram: Вызывается answerCallbackQuery с кратким всплывающим уведомлением.


>>> Сценарий 3: Контролируемая подача отклика на HeadHunter (11 защитных гейтов)
1. Триггер: Оператор в консоли запускает:  
   python -m ai_assistant.cli submit <vacancy_id> --confirm-submit
2. Безопасное подключение: browser_executor.py подключается по протоколу CDP к порту 9222 уже открытого браузера Chrome. Переход по URL вида applicant/vacancy_response категорически запрещен (во избежание автоотклика HeadHunter без ведома пользователя).
3. Считывание формы (Read-only): hh_extractor.py считывает DOM открытой вкладки, находит поля вопросов и формирует снимок структуры.
4. Генерация ответов: application_qa.py отвечает на вопросы анкеты strictly truth-only на основе candidate_profile.json. Если факт неизвестен, генерация прерывается и требует HUMAN_REVIEW.
5. Планирование и CDP-предзаполнение: prefill_plan.py формирует план, а prefill_execute.py устанавливает значения полей через нативные прототипы React в DOM без кликов по кнопкам отправки.
6. Контроль гейтов (hh_submission.py): Проверяются 11 обязательных условий:
   1. GATE_SUBMIT_ALLOWED — флаг разрешения отправки.
   2. GATE_REVIEW_APPROVED — наличие одобренного ревью в БД.
   3. GATE_FINGERPRINT_MATCH — совпадение хеша формы на странице с хешем в ревью.
   4. GATE_URL_VALID — соответствие URL текущей вакансии.
   5. GATE_VACANCY_MATCH — совпадение ID вакансии.
   6. GATE_PROFILE_LOADED — корректность загруженного профиля.
   7. GATE_COVER_LETTER_READY — наличие сгенерированного письма.
   8. GATE_NO_UNKNOWN_QUESTIONS — отсутствие неотвеченных обязательных вопросов.
   9. GATE_NOT_ALREADY_APPLIED — отсутствие статуса ранее поданного отклика.
   10. GATE_NO_PREVIOUS_SUBMISSION_ATTEMPT — отсутствие незавершенных попыток.
   11. GATE_HUMAN_CONFIRMED — наличие явного флага --confirm-submit.
7. Отправка: Производится ровно один физический клик по кнопке отправки.
8. Верификация: submission_verifier.py считывает DOM после отправки (баннер успеха, исчезновение формы). Статус переводится в APPLIED только при явном подтверждении. В случае неопределенности выставляется AMBIGUOUS_POST_SUBMIT (повторные попытки запрещены).


--------------------------------------------------------------------------------
3.4. Схема данных (SQLite)
--------------------------------------------------------------------------------
В базе данных state.db используется 24 таблицы:
1. vacancies — основной реестр найденных вакансий (поля: stable_id, source, title, company, salary_min, salary_max, job_url, match_score, state, raw_data и др.).
2. processed_vacancies — исторический реестр хешей обработанных вакансий.
3. canonical_vacancies / vacancy_aliases — таблицы дедупликации и связи дублей с канонической сущностью.
4. vacancy_eligibility — статус проверки ограничений (страна, ремоут).
5. deep_analysis — результаты глубокого анализа LLM (fit score, ключевые навыки, анализ рисков).
6. application_packages — сгенерированные пакеты отклика (резюме, сопроводительное письмо, Q&A).
7. application_tracking / application_status_history — конечный автомат статусов откликов (DISCOVERED, ANALYZED, READY_TO_APPLY, APPLIED, INTERVIEW, REJECTED, WITHDRAWN).
8. application_queue — очередь откликов с приоритетами и рангом.
9. application_reviews — записи человеческого ревью формы и решения оператора.
10. application_submissions / submission_verifications — аудит физических откликов и результатов верификации.
11. browser_preparations — снимки состояния предзаполнения формы в браузере.
12. hh_message_events / hh_questionnaires / hh_applications / hh_application_transitions — подсистема чатов и анкет HeadHunter.
13. autonomous_notifications / interview_events / autonomous_cycle_runs / autonomous_conversation_audits — аудит автономного цикла.
14. telegram_delivery_records — лог доставки дайджестов с уникальными ключами идемпотентности.
15. telegram_feedback_records — полный лог нажатий кнопок фидбека в Telegram.

Миграции:
- Специализированный инструмент миграций (Alembic) отсутствует.
- Схема создается при каждом старте через вызов init_db() конструкциями CREATE TABLE IF NOT EXISTS.
- Обновления схемы реализованы в виде блоков try: cursor.execute("ALTER TABLE ... ADD COLUMN ...") except sqlite3.OperationalError: pass.

*Обоснование:* Фундамент предметной области — Pydantic-модели вакансий, результатов матчинга, классов решений и приоритетов.

"""
Pydantic schemas for vacancies, candidate profile, and analysis results.
"""

import hashlib
import re
from datetime import datetime
from enum import Enum
from typing import Any, Dict, List, Optional
from pydantic import BaseModel, Field


class MatchDecision(str, Enum):
    APPLY = "APPLY"
    REVIEW = "REVIEW"
    REJECT = "REJECT"


class DecisionClass(str, Enum):
    STRONG_MATCH = "STRONG_MATCH"
    MATCH = "MATCH"
    STRETCH = "STRETCH"
    BORDERLINE = "BORDERLINE"
    REJECT = "REJECT"


class RolePriority(str, Enum):
    P1 = "P1"
    P2 = "P2"
    P3 = "P3"
    UNMAPPED = "UNMAPPED"
    EXCLUDED = "EXCLUDED"


class Vacancy(BaseModel):
    id: Optional[str] = None
    source: str
    source_job_id: str
    title: str
    company: Optional[str] = None
    description: Optional[str] = None
    location: Optional[str] = None
    country_restrictions: Optional[List[str]] = None
    timezone_restrictions: Optional[List[str]] = None
    salary_min: Optional[float] = None
    salary_max: Optional[float] = None
    salary_currency: Optional[str] = None
    employment_type: Optional[str] = None
    job_url: str
    application_url: Optional[str] = None
    published_at: Optional[datetime] = None
    first_seen_at: Optional[datetime] = None
    last_seen_at: Optional[datetime] = None
    state: str = "NEW"
    raw_data: Optional[Dict[str, Any]] = None
    match_score: Optional[float] = None
    match_decision: Optional[str] = None
    match_reasons: Optional[List[str]] = None
    match_strengths: Optional[List[str]] = None
    match_gaps: Optional[List[str]] = None

    def stable_id(self) -> str:
        """
        Deterministic, collision-safe identifier:
          - If source_job_id is non-empty: f"{source}:{source_job_id}"
          - If source_job_id is missing:   f"{source}:url_{sha256(canonical_url)[:16]}"
        """
        if self.source_job_id:
            return f"{self.source}:{self.source_job_id}"
        norm_url = re.sub(r"[?#].*$", "", self.job_url.strip().lower())
        h = hashlib.sha256(norm_url.encode("utf-8")).hexdigest()[:16]
        return f"{self.source}:url_{h}"


class MatchResult(BaseModel):
    score: float = Field(ge=0, le=100)
    decision: MatchDecision
    decision_class: Optional[DecisionClass] = None
    reasons: List[str] = Field(default_factory=list)
    strengths: List[str] = Field(default_factory=list)
    gaps: List[str] = Field(default_factory=list)
    dimensions: Optional[Dict[str, Any]] = None
    role_priority: Optional[RolePriority] = None
    ranking_score: Optional[float] = None
    preference_adjustment: Optional[float] = None

>>> 2. `ai_assistant/hh_submission.py`
*Обоснование:* Сердцевина безопасности откликов — реализация 11 обязательных защитных шлюзов перед физическим нажатием кнопки отклика на HeadHunter.
--------------------------------------------------------------------------------
"""
Stage 20I: HH Controlled Submission & Gates
Implements strict gates before single-click submit and submission record persistence.
"""
from dataclasses import dataclass
from typing import List, Optional
from datetime import datetime, timezone
import json
import logging
from enum import Enum

from .db import (
    get_application_review,
    get_connection,
    save_application_submission,
    get_submission,
    init_db
)
from .application_review import ReviewStatus
from .candidate_profile import load_candidate_profile
from .application_qa import answer_question, AnswerDecision

logger = logging.getLogger(__name__)

class GateName(str, Enum):
    GATE_SUBMIT_ALLOWED = "submit_allowed"
    GATE_REVIEW_APPROVED = "review_approved"
    GATE_FINGERPRINT_MATCH = "fingerprint_match"
    GATE_URL_VALID = "url_valid"
    GATE_VACANCY_MATCH = "vacancy_match"
    GATE_PROFILE_LOADED = "profile_loaded"
    GATE_COVER_LETTER_READY = "cover_letter_ready"
    GATE_NO_UNKNOWN_QUESTIONS = "no_unknown_questions"
    GATE_NOT_ALREADY_APPLIED = "not_already_applied"
    GATE_NO_PREVIOUS_SUBMISSION_ATTEMPT = "no_previous_submission_attempt"
    GATE_HUMAN_CONFIRMED = "human_confirmed"

@dataclass
class GateCheckResult:
    passed: bool
    failed_gate: Optional[GateName] = None
    reason: str = ""
    details: dict = None

class HHSubmissionGates:
    @staticmethod
    def check_all_gates(
        vacancy_stable_id: str,
        current_url: str,
        form_snapshot: dict,
        human_confirmed: bool = False,
        dry_run: bool = False
    ) -> GateCheckResult:
        init_db()
        review = get_application_review(vacancy_stable_id)
        if not review:
            return GateCheckResult(False, GateName.GATE_REVIEW_APPROVED, "No review found for vacancy")
        if review.status != ReviewStatus.APPROVED:
            return GateCheckResult(False, GateName.GATE_REVIEW_APPROVED, f"Review is {review.status.value}, expected APPROVED")

        expected_fp = review.form_fingerprint
        actual_fp = form_snapshot.get("fingerprint")
        if not expected_fp or not actual_fp or expected_fp != actual_fp:
            return GateCheckResult(False, GateName.GATE_FINGERPRINT_MATCH, f"Fingerprint mismatch: review={expected_fp}, page={actual_fp}")

        if not current_url.startswith("https://hh.ru/"):
            return GateCheckResult(False, GateName.GATE_URL_VALID, f"Invalid URL: {current_url}")

        expected_job_id = vacancy_stable_id.split(":")[-1]
        if f"vacancyId={expected_job_id}" not in current_url and f"/vacancy/{expected_job_id}" not in current_url:
            return GateCheckResult(False, GateName.GATE_VACANCY_MATCH, f"URL {current_url} does not match vacancy id {expected_job_id}")

        profile = load_candidate_profile()
        if not profile:
            return GateCheckResult(False, GateName.GATE_PROFILE_LOADED, "Candidate profile could not be loaded")

        cover_letter = form_snapshot.get("cover_letter")
        if not cover_letter or len(cover_letter.strip()) < 10:
            return GateCheckResult(False, GateName.GATE_COVER_LETTER_READY, "Cover letter is missing or too short")

        fields = form_snapshot.get("fields", [])
        for f in fields:
            f_type = f.get("type")
            label = f.get("label", "")
            if f_type in ("textarea", "text") and label:
                ans = answer_question(label, profile)
                if ans.decision != AnswerDecision.ANSWERED:
                    return GateCheckResult(False, GateName.GATE_NO_UNKNOWN_QUESTIONS, f"Question requires human review: {label}")

        existing_sub = get_submission(vacancy_stable_id)

def compute_file_sha256(path: Path) -> Optional[str]:
    if not path.exists() or not path.is_file():
        return None
    h = hashlib.sha256()
    h.update(path.read_bytes())
    return h.hexdigest().upper()
