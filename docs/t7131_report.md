## §1 Штатный путь правки найден

T7.13 упёрся в то, что резюме «не редактируется». Причина оказалась не в интерфейсе HH,
а в том, **как** я посылал клик.

**Адреса, которыми правится резюме** (проверены навигацией, не угаданы):

| адрес | что это |
|---|---|
| `/resume/edit/<hash>/position` | название / должность |
| `/resume/edit/<hash>/about` | «Обо мне», textarea `resume-editor-about` |
| `/resume/edit/<hash>/keySkills` | навыки, чипсы `chips-trigger-chip-<имя>` |
| `/resume/edit/<hash>/skillsLevels?fromBlock=keySkills` | уровни навыков (появляется **после** сохранения навыков) |
| `/resume/edit/<hash>/skills` | **404** — такого раздела нет |
| `/profile/edit/experience/<id>?resumeFrom=<hash>` | запись опыта (профильная, не резюмная) |
| `/profile/resume/professional_role?resume=<hash>` | мастер профессии (для нового резюме) |

Сохранение в любом разделе — одна кнопка `resume-partial-edit-save` («Сохранить»).
После сохранения навыков HH **обязательно** уводит на `skillsLevels`, и там надо нажать
«Сохранить» ещё раз — иначе шаг остаётся незакрытым.

**Клик.** `el.click()` из JavaScript HH принимает не везде, поэтому настоящий клик —
это `Input.dispatchMouseEvent`. Но у него два условия, и оба стоили времени:

1. **`mouseMoved` первым.** Без него ссылка «Редактировать» остаётся инертной: press/release
   попадают в элемент, который ещё не «вооружился», и ничего не происходит. Именно поэтому
   наивный клик в T7.13 «ничего не делал», хотя сеть показывала, что запрос уходил.
2. **Вкладка должна быть видимой.** `document.visibilityState === "hidden"` — Chrome
   **молча выбрасывает** мышь: событий не доходит ни одного, а команда рапортует об успехе.
   Проверено ловушкой на `document` в фазе перехвата: лог пуст.

   Переключает видимость **только** `Target.activateTarget` на browser-уровне.
   `Page.bringToFront` не переключает — `visibilityState` остаётся `hidden`.

**Виджет навыков.** Видимое поле `chips-trigger-input` — **`readOnly`**, пока виджет не
сфокусирован настоящей мышью; после фокуса оно становится обычным текстовым полем и
принимает `Input.insertText`. (Поле `chips-input-suggest-search` появляется лишь в
некоторых состояниях виджета и как точка входа ненадёжно.) Удаление чипсы вызывает
**внутреннюю навигацию** HH, которая убивает контекст `Runtime.evaluate` — поэтому удаления
делаются батчами ≤ 6, с перечитыванием состояния после каждого.

**Мастер профессии** (для нового дубля): карточка `resume-profile-card-select-job` →
комбобокс `resume-profile-position-input` → «Сохранить и продолжить»
(`resume-profile-next-screen`) → модалка «Уточните специальность»
(`category-modal-submit`), дерево `tree-selector-item-text-category-11` →
дочерняя `tree-selector-item-121`. Дубль резюме — меню карточки
`resume-list-action-more` → `operations-list-duplicate-resume`.

**Находка:** HH по умолчанию подставляет **последнее использованное** резюме, а не
подходящее по смыслу. На двух Bitrix24/CRM-вакансиях по умолчанию стоял
«Инженер технической поддержки» — то есть **отправка «как есть» ушла бы с не тем резюме**.
Это надо помнить при будущей отправке: селект проверять руками каждый раз.

Плашка `hidden-resume-warning` на всех трёх формах **свёрнута** (`max-height: 0`) — то есть
видимость резюме препятствием не является. Текст плашки, если она развернётся:
«Чтобы откликнуться на эту вакансию, поменяйте видимость резюме на «Видно всем
работодателям, зарегистрированным на hh.ru»».
