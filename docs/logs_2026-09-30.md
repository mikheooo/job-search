### Результат

**Работает живьём:** владение (lease ACQUIRED → release после сегмента), **AUTH PASS ×3**
(сессия переживает перезапуск процесса без ручного логина), навигация 12/12 (`complete` + SSR,

`visible_chrome_windows=0` и фокус ни разу не в chrome.

**Не работает:** поиск. **34 запуска запроса → 0 карточек**, `discovered_count=0`.

**Причина — одна строка.** `READ_CARDS_JS` ищет контейнер `[data-qa="serp-item"]`, которого на
живой SERP **нет** (замер: 0), а живой контейнер — `[data-qa="vacancy-serp__vacancy"]` (50),
при том что `a[data-qa="serp-item__title"]` жив (50). SERP при этом полностью отрисован:
«Найдено 103 вакансии «IT Support»», 50 карточек, captcha нет.

**Контрфакт:** подменил эту строку **только в памяти процесса** (файл не тронут) и запустил
настоящий `run_autonomous_cycle` → `IT Support=20, Bitrix24=20, discovered=40, matched=2,
read=10`, после — lease ABSENT. **0 → 40.** Значит дефект ровно в этой строке, и ничего больше.

### Грабли, которые стоили времени

- **`SUBMIT_ALLOWED` читать через `config.submit_allowed()`, не через `os.environ`.**
  `.env` держит `true`, `load_dotenv(override=True)` затирает окружение ⇒ после импорта
  `os.environ` показывает `'true'`. Мой первый раннер из-за этого ложно отказался запускаться;
  сам гейт проекта всё это время работал верно.
- **SERP гидрируется после `complete`:** первое чтение — 20 карточек, через ~3 с — 50.
- **Хук окружения `safe-delete`** (порог 50 удалений на «turn») прервал релиз lease и оставил
  запись с мёртвым владельцем; контракт назвал её `LIVE`, не `STALE`. Убрал через
  `lease.clear_lease(session_id)`, повторный прогон прошёл полностью.
- **`REQUIRED_STRUCTURED_FIELDS` — ключи snapshot,** а не словаря preflight: правильный ответ
  даёт `preflight["fields_missing"]`. Мой первый чекер смотрел не туда.
- **`workExperience`/`workSchedule` — в `short_vacancy`,** а `workFormats`/`compensation`/`area` —
  в `vacancy`. Чтение не из того места даёт ложный `None`.

## T7.26.2 — починка селекторов HH + живое подтверждение (VERDICT: PASS)

Отчёт — `docs/t7262_report.md`. Правлен **один** файл: `ai_assistant/hh_readonly_operation.py`
`156bf29a…` (22 064 B) → `1a2c073b…` (23 808 B). `cli.py` не тронут.

### Что сделано

- **Контейнер:** оба скрипта (`COUNT_RESULTS_JS`, `READ_CARDS_JS`) теперь берут селектор из
  **одной** константы `CARD_CONTAINER_SELECTORS`/`CARD_CONTAINER_SELECTOR` —
  `[data-qa="vacancy-serp__vacancy"]` первым, старый как фолбэк. Дубль в двух блоках и был
  причиной слепоты.
- **Зарплата — дефект оказался двойным.** `data-qa` на сумме **нет вообще**: сумма это **первый
  прямой `SPAN`-ребёнок** блока `compensation-labels`, без `data-qa`. Единственный `data-qa` в
  блоке — `vacancy-serp__vacancy-compensation-frequency-TWICE_PER_MONTH` на `SPAN` с текстом
  **«Выплаты: Два раза в месяц»**. Поэтому старый фолбэк `[data-qa*="compensation"]` возвращал
  **частоту выплат как зарплату** — не `None`, а уверенно неверное значение. Убран. Новый:
  `[data-qa="vacancy-serp__vacancy-compensation"], [class*="compensation-labels"] > span`.
- **Перекрёстная проверка (сильнее самоотчёта):** значение из карточки SERP против
  `vacancy.compensation` со страницы — сходится на **10/10**, включая gross/net («на руки» ↔
  `gross=false`, «до вычета налогов» ↔ `gross=true`). Всего прочитано 23 карточки, 13 с зарплатой,
  все значения верные.

### Грабли

- **Наивный зонд невидимости врёт.** `Get-Process chrome` дал `visible_chrome_windows=1` — это
  **личный** Chrome оператора (47–49 процессов). Правильно: сначала отобрать процессы по

  `our_visible_windows=0` в 6/6 замеров с живым браузером, `foreground_is_ours=False` 14/14.
- **`stdout` в Windows переводит `\n`→`\r\n`** ⇒ при восстановлении файла «байт в байт» писать
  через `sys.stdout.buffer`, иначе хеш не сойдётся (+484 B на 484 строках). На этом A/B споткнулся.

  файле ⇒ это регрессия T7.26, не моя.

  карточки при `expression == ro.READ_CARDS_JS`; устаревший селектор объект как раз сохраняет.
  Отсюда — DOM-тест на реальном chromium с негативным контролем.
