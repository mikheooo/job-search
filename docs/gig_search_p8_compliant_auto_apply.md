## Implemented behavior

The official adapter is in [freelancer.py](../ai_assistant/gig/submission/freelancer.py). It uses the documented API host only, OAuth from `FLN_OAUTH_TOKEN`, no browser-submit path, no cookies, no redirects, and no automatic HTTP retries. The transport itself checks written-access, storage, retention, scope, and expiry evidence; a bid POST also needs a single-use engine permit tied to the exact approved payload. Direct raw POST calls therefore stop before networking. It suppresses API exception bodies and authorization data. After a lost or ambiguous POST, it reconciles by reading own bids and never repeats the POST.

[engine.py](../ai_assistant/gig/submission/engine.py) refreshes project state, description/scope/budget hashes, bid count, economics, and competition-adjusted First Money score. It checks OPEN status, capability, risk, claims and references, account readiness, price/time/currency integrity, milestone alignment, provider/local rate limits, express written bid permission, strong-encryption evidence, and a separate written permission reference for API-derived field retention under API Terms §5. It applies atomic persistent deduplication and reserves the project before POST. A confirmed bid ID, API request ID, actual price/time, bid count, submitted time, proposal hash, description hash, and `SUBMITTED` status commit to the tracker with the outbox record.

The CLI is `python -m ai_assistant.gig.submission.cli apply --pack <DPAPI_FILE> --policy <VERIFIED_POLICY_JSON> --submit --approve <PAYLOAD_SHA256>`. It uses the separate DPAPI tracker and refuses plaintext tracker files. Only packs with a current bounded-retention envelope can be loaded; old unbounded Stage A packs are not eligible for submission. Dry-run is the default; approval must match the exact payload hash. Policy must separately attest `api_data_retention_permitted: true`, a `retention_permission_reference`, and numeric `api_data_retention_seconds` between 1 and 86,400; the encrypted tracker enforces that expiry. No such provider evidence is currently available. `monitor` supports read-only own-bid/project status, award, and closure detection after policy and account checks pass. Replies stay `UNKNOWN` until a documented entitled read operation is verified. Monitoring runs in the foreground; no Windows service or recurring scheduler was installed.

P8 proposal and payload artifacts use Windows DPAPI current-user encryption: [prepared packs](../artifacts/p8/stage_a_five_prepared.dpapi.json), [dry-run payloads](../artifacts/p8/stage_a_five_dryrun.dpapi.json), and [independent Stage B QA](../artifacts/p8/stage_b_independent_qa.dpapi.json). The P8 tracker stores SQLite only in memory while open and writes its database image through DPAPI; unrecognized or legacy plaintext tracker files fail closed. Expired rows are deleted when the tracker is next opened; expired DPAPI artifacts are deleted on load and swept from managed P6/P8 output folders when those workflows run. Historical P8 Stage A files predate these retention envelopes and therefore are ineligible for a new apply. Legacy P6/P7 finalizer scripts and the direct P7 collector are disabled because they read or write unbounded plaintext artifacts. The existing `tracker_before_p8.sqlite` backup and older P6/P7 artifacts remain preserved as historical user data, are not migrated or read by the new workflow, and are not eligible for live submission; they are outside the new 24-hour retention controls.
