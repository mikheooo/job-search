## 1. Что это

Автоматизация поиска работы: сбор вакансий с HH.ru → скоринг → подготовка отклика →
ворота безопасности → отправка. Питон, SQLite, Playwright/CDP, свой headless Chrome.

**Главное правило проекта — не навреди.** Отклик отправляется только через ворота
безопасности, все остальные ступени ничего наружу не пишут. Именно поэтому в проекте так
много проверок: «ничего не отправилось» доказывается, а не подразумевается.

## 3. Что решено по существу

### Живой браузер
HH управляется **своим** headless Chrome на порту **9111** и на **своём** профиле (отдельный
от рабочего браузера), режим задаётся явно: `HH_BROWSER_MODE=headless`. Исторический путь
через BrowserOS (9110) остался как откат.

**Владение браузером закрыто:** безвладельных продакшн-путей было 10, стало 0. Примитивов
три, владеемых операций девять. Регрессия «читали раньше отрисовки» вылечена тем, что
после открытия вкладки ждём **смену URL и отрисовку**, а не паузу.

### Поиск и отбор
Найден и починен главный дефект: результаты разных запросов сливались в порядке обхода,
и читались **первые N**. Значит короткий список зависел от порядка строки запросов —
при `read_limit=10` на «IT Support + Bitrix24» все 10 чтений шли из IT Support.

**T7.27 (последняя задача) — поиск работал, а выбор нет.** Теперь отбор идёт
**round-robin по направлениям**: 5 направлений, по одному кандидату за круг, плюс дешёвый
предварительный ранг по карточке (бюджет, **не** найм).

Живой замер: **723** найдено, **30/30 целевых, по 6 на направление**,
`OTHER`/`OFF_PROFILE` — **0**. Контрольная точка со старой политикой дала 5+3 слота
в доборные корзины при 269 доступных целевых — это и есть доказательство починки.

### География — главный вывод
Полоса A (можно из Таиланда) — **0 из 723**. Ни один работодатель не написал, что можно
работать из Таиланда. Следствие: `READY_FOR_APPLICATION` обречён на ноль **по построению**,
и каждый отклик несёт вопрос «возможна ли работа из Таиланда?».

Полоса B (удалёнка есть, про Таиланд молчат) — **не разрешение**. Вопрос задаётся всегда.

## 7. Грабли (короткий список)

Полная таблица — 24 правила — в `docs/project_memory.md`. Здесь то, что больнее всего:

- **Скрытая вкладка съедает мышь.** Клик бьёт только внутри вьюпорта → `scrollIntoView`,
  перемерить, `elementFromPoint`.
- **Форма отклика живёт только в памяти вкладки.** Перезагрузка её теряет.
- **`alreadyApplied` остаётся `false`** → по нему проверять **нельзя**. Верные признаки:
  `usedResumeIds`, `negotiations.total`, `topicList[0].responded`, DOM `…-top-again`.
- **«Нужно ответить на вопросы работодателя» — статичная фраза**, она ничего не значит.
- **`netstat | grep 9111` — ловушка:** после прогона сотни `TIME_WAIT` (закрытые
  соединения). Смотреть только `LISTENING`.
- **`os.kill(pid, 0)` в Windows — это не проверка, а убийство.** Нужен
  `OpenProcess` + `GetExitCodeProcess`.
- **Голое слово `support` в названии не делает роль техподдержкой.** «Менеджер по развитию
  бизнеса (услуга Professional Support)» возглавлял TOP-15, пока не поправили.
- **Ноль в корзине — возможно, следствие построения, а не провал.** Прежде чем объявлять
  дефект, проверь: «не сработало» или «условие невыполнимо по данным»?

```bash

  tools/.t727/build_shortlist.py --read-limit 30 --label t727b

# пересборка отчёта из снимка, без браузера
  ... --from-raw
```

**Запреты, которые важнее удобства:** не отправлять (ни откликов, ни сообщений, ни анкет),
не править `ai_assistant/cli.py`, не трогать проект `gig`, не пушить.
`SUBMIT_ALLOWED` — только в командной строке живой команды, **никогда** в окружении:
в окружении она ломает ~97 тестов отправки.

## 9. Как устроена память проекта

Знание живёт в трёх местах, и это сделано намеренно:

| Слой | Где | Переживёт смену машины? |
|---|---|---|
| Разборы задач | `docs/t*_report.md` (48 файлов) | да, в git |
| Конвенции и грабли | `docs/project_memory.md` | да, в git |
| Хроника по дням | `docs/memory_details.md` (~300 КБ) | да, в git |
| Сырые снимки прогонов | `tools/.t7xx/*.json` | **нет** — локально, с описью и хешами в `docs/task_artifacts.md` |

Правило деления: **скрипт — в историю** (он отвечает «как ты это измерил»), **дамп — нет**
(он воспроизводим повторным запросом). Пропасть молча снимок не может — он в описи.
