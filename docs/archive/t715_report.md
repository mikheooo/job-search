## Инцидент: клик по кнопке отправки, который ничего не отправил

Первый клик по «Откликнуться» на Академии Йоги **не отправил ничего**. При этом форма была в полном
порядке: кнопка `BUTTON`, `type=submit`, `disabled=false`, размер `540×48`, **единственная** `type=submit`
на странице, оверлеев 0, письмо на месте (589 символов), шапка про «вопросы работодателя» — статическое
описание (вопросов нет).

Причина оказалась геометрической:

```
viewport        vw=585  vh=801
document        scrollY=119  scrollHeight=3211
кнопка          top=855  bottom=903
центр           (285, 879) — ниже нижней границы вьюпорта
elementFromPoint(285,879) -> null
```

`Input.dispatchMouseEvent` в координатах за пределами вьюпорта не попадает ни во что и **не сообщает
об ошибке**. Отправки не произошло, но и «сломанного» состояния не возникло: `usedResumeIds` остался
`[]`, кнопка на месте.

**Лечение:** `scrollIntoView({block:"center"})` → перемерить `getBoundingClientRect()` (после прокрутки
он другой) → клик по новому центру `(285,401)`, где `elementFromPoint` возвращает сам
`vacancy-response-submit-popup`. Этот клик и отправил отклик.

**Проверка перед кликом, которая ловит это заранее:** не «есть ли кнопка», а попадание центра во
вьюпорт и `elementFromPoint(cx, cy)` по цели.

3. Текст страницы вакансии: «**Вы откликнулись**», «Отклик другим резюме», «Чат», «Связаться».
4. Запись в `negotiations.topicList` с нужным `vacancyId`, `resumeId`, `hasResponseLetter: true`,
   `initialTopicType: "RESPONSE_BY_APPLICANT"`.

## Сверка локального состояния

Только стоковые функции, без новой подсистемы (`tools/.t715_reconcile_evateam.py`,
`tools/.t715_reconcile_two.py`):

- `application_tracking.set_application_status(SID, SUBMITTED, …)` — `SUBMITTED` ручной статус,
  `sync_application_tracking` его не перезапишет, и он вне `ALLOWED_TRACKING_STATUSES`;
- `db.save_submission(…, status="SUBMITTED", executor_version="manual-browser-v1",
  submission_id="hh-manual-<id>-<MSK>")` — `SUBMITTED` входит в `BLOCKED_SUBMISSION_STATUSES`;
- `hh_applications` **намеренно не тронут** — это машина состояний автономного агента, а у ручного
  отклика нет HH `application_id`.

Предохранитель проверен замером: `can_submit` для всех трёх вакансий стал `False` с причинами
«Tracking status 'SUBMITTED' is not in allowed whitelist» и «Existing submission record has status
'SUBMITTED'». Повторный запуск скрипта отвечает `REFUSING: a record already exists`.

Хеш письма в payload — sha256 по `strip()`-нутому тексту (в проекте принят этот вариант: у EvaTeam
сырые байты дают `40634ddc1ef2bb35`, strip — `ce6203204f66683a`).
