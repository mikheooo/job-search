job-search — конвейер вакансий и откликов

Персональная система: сбор удалённых вакансий и гигов, нормализация и дедупликация, скоринг по профилю кандидата, подготовка пакета отклика, жизненный цикл в SQLite и доставка дайджеста в Telegram. Внешние действия закрыты предохранителями: REVIEW по умолчанию, AUTO только по явному kill-switch, факты не выдумываются.

Python 3.11 SQLite WAL · state.db Playwright + raw CDP OpenAI-совместимый LLM + fallback FastAPI · дашборд Windows Task Scheduler Telegram Bot API

Карта модулей

Один канонический конвейер и несколько независимых точек входа.

Сбор

adapters/* — Himalayas, RemoteOK, WeWorkRemotely, Habr Career. run_multi_source_discovery.py — Hirify, GeekJob, Bangkok ATS, LinkedIn, Telegram-каналы.

Нормализация и дедуп

normalizer.py приводит к схеме Vacancy, vacancy_identity.py считает канонический ID и алиасы.

Фильтры

eligibility.py — гео и remote-допустимость, remote_filter.py — строгое «100% remote», prefilter.py — стоп-слова и зарплатный порог.

Скоринг

matcher.py — жёсткие ограничения, взвешенный скор, decision_class и role_priority. job_analyzer.py — LLM-анализ с offline-fallback.

Пакет отклика

application_prep.py — резюме и письмо, application_qa.py — truth-only ответы, application_queue.py — приоритеты.

Браузер и отправка

hh_extractor.py, prefill_plan.py, prefill_execute.py — React-safe заполнение. hh_submission.py — 11 гейтов и один клик.

HH-автономность

hh_autopilot.py — цикл откликов, hh_autonomous_agent.py — сообщения и интервью, hh_message_reply.py — read-only чтение диалогов.

Доставка

cli.py — export_digest_cmd, integrations/hermes/job_search_fetcher.py — канонический диспетчер, telegram_notifier.py — клавиатура fb:*.

Обратная связь

telegram_feedback.py — владелец, идемпотентность, provenance, telegram_control_bot.py — пульт @jobsassistbot.

Эксплуатация

runner.py — лок, ротация логов, circuit breaker, маскировка секретов, application_integrity.py — аудит целостности.

Наблюдения и расхождения

Что важно знать перед тем, как доверять схеме.

расхождение

Документация vs код отправки

README и PROJECT_STATE.md обещают prepare-only и --confirm-submit. Фактически hh_autopilot.submit_vacancy() сам ставит SUBMIT_ALLOWED=true и кликает отправку, а в preflight.json пишет auto_submit_authorized: true.

сломано

Отсутствующие модули

hh_readonly_operation.py и hh_browser_lease.py не найдены ни на диске, ни в git. Их импортируют автопилот и его раннер, поэтому поиск вакансий падает в {"status": "ERROR"}.

риск

Два планировщика на один fetcher

Задача Windows и Hermes cron приходят в один файл. Спасает только отдельный job_search_fetcher.lock, иначе ловится database is locked.

риск

Дублирование отправки

run_multi_source_discovery.py и hh_autopilot.py шлют в Telegram напрямую через urllib, минуя TelegramNotifier: общей идемпотентности и ретрай-политики у них нет.

инвариант

Fail-closed

Неопределённый исход не повторяется: дайджест уходит в AMBIGUOUS, отклик — в SUBMISSION_UNKNOWN. Разбор только вручную.

инвариант

Truth-only

Нет подтверждённого факта — нет ответа. Вопрос уходит в HUMAN_REVIEW, а не в догадку.
